# Repository Guidelines

## Project Structure & Module Organization
- `main.py` defines the FastAPI app, middleware, and router registration.
- `routers/` holds API endpoints; each module should export a `router` instance.
- `services/` contains business logic, background sync/scheduler code, and shared helpers.
- `services/schemas/` defines request/response models used by routers.
- `integrations/` houses external provider integrations (for example, GitHub).
- `models.py` and `database.py` define SQLModel entities and DB session helpers.
- `migrations/` and `alembic.ini` manage schema changes.
- `admin_templates/` and `admin_statics/` power the admin UI.

## Build, Test, and Development Commands
- `uvicorn main:app --reload` starts the API locally with reload.
- `make alembic-upgrade to=head` applies database migrations.
- `make alembic-revision message="add_users"` creates an autogenerated migration.
- `make alembic-revision-empty message="manual_step"` creates an empty migration.
- `make alembic-history` and `make alembic-current` inspect migration state.

## Coding Style & Naming Conventions
- Use 4-space indentation and PEP 8 style; keep type hints consistent with existing code.
- Name modules, functions, and variables in `snake_case`; classes in `PascalCase`.
- Keep routing thin: parse inputs in `routers/`, delegate logic to `services/`.
- Add new API schemas under `services/schemas/` and reuse them across routers.

## Testing Guidelines
- No automated test framework is configured today. Use `test_main.http` for manual API checks.
- If you introduce tests, place them in `tests/` with `test_*.py` naming and add pytest to `pyproject.toml`.
- Coverage targets are not defined; prioritize auth, sync, and scoring paths when adding tests.

## Commit & Pull Request Guidelines
- Commit messages follow imperative, sentence-case summaries (example: "Add search functionality to list views").
- PRs should include a clear summary, linked issue (if any), migration notes, and test evidence.
- Include screenshots for admin UI changes and list any new or changed env vars.

## Configuration & Secrets
- Configuration loads from `.env` via `settings.py`. `database_url` is required.
- Never commit secrets such as Clerk or GitHub credentials; document required values in PRs.
